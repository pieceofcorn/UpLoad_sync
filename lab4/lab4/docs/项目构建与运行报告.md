## 3. 本地复现

在 PowerShell 中从工程根目录按顺序运行。仿真脚本会更新本地工程和 XSim 日志，构建脚本会重置 Vivado 的 `synth_1`、`impl_1` 运行并更新现有产物。以下命令用于需要重新验证或重建时复现。

```powershell
Set-Location -LiteralPath 'E:\projects\github\lab4\lab4'
$vivado = 'D:\AMDDesignTools\2025.2\Vivado\bin\vivado.bat'

# Core 行为仿真
& $vivado -mode batch -source .\scripts\run_sim.tcl -tclargs core
if ($LASTEXITCODE -ne 0) { throw 'Core 仿真失败，检查 Vivado 日志。' }

# Board 行为仿真
& $vivado -mode batch -source .\scripts\run_sim.tcl -tclargs board
if ($LASTEXITCODE -ne 0) { throw 'Board 仿真失败，检查 Vivado 日志。' }

# 综合、实现、报告和 Bitstream，4 个并行作业
& $vivado -mode batch -source .\scripts\run_build.tcl -tclargs 4 2>&1 |
    Tee-Object -FilePath .\build.log
if ($LASTEXITCODE -ne 0) { throw 'FPGA 构建失败，检查 build.log。' }

Get-Item -LiteralPath .\build\lab4.runs\impl_1\lab4_top.bit
```

1. `create_project.tcl` 根据脚本位置确定工程根目录，将设计、仿真和约束文件各自加入对应文件集。设计顶层为 `lab4_top`，器件检查值为 `xc7a100tfgg484-1`。
2. `run_sim.tcl` 选择 `tb_alu_core` 或 `tb_lab4_top`，删除对应的旧状态文件，启动 XSim 行为仿真并执行 `run all`。通过条件是本轮状态为 PASS、错误数为 0 且达到最低检查数。状态文件保存在 `build/lab4.sim/sim_1/behav/xsim`。
3. `run_build.tcl` 先综合并输出综合资源及时序报告，再启动实现直到 `write_bitstream`。综合将 Verilog 转为目标器件网表，实现阶段据约束进行优化、布局与布线。脚本读取实现结果生成资源、时序和 DRC 报告，并验证预期比特流文件存在。

脚本依据见 [工程创建](../scripts/create_project.tcl)、[行为仿真](../scripts/run_sim.tcl) 与 [FPGA 构建](../scripts/run_build.tcl)。
